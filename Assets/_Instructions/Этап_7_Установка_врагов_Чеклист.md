# Чеклист: Установка системы врагов

Этот документ содержит полный пошаговый чеклист для установки системы врагов на основе уроков 7.1–7.4.

---

## ✅ Шаг 1: EnemyData (ScriptableObject)

**Цель:** Создать ScriptableObject с данными врага.

### 1.1. Создание скрипта EnemyData
- [ ] В папке `Assets/_Scripts/Enemies/` создан скрипт `EnemyData.cs`
- [ ] Класс наследуется от `ScriptableObject` (не `MonoBehaviour`)
- [ ] Добавлен атрибут `[CreateAssetMenu]` с меню `"Game Data/Enemy Data"`
- [ ] Поля: `enemyName`, `enemyType`, `maxHealth`, `moveSpeed`, `damage`, `attackRange`, `detectionRange`, `experienceReward`, `prefab`

### 1.2. Создание ассетов EnemyData
- [ ] В папке `Assets/_ScriptableObjects/Enemies/` созданы ассеты:
  - [ ] `Enemy_Goblin_Default` (Health: 50, Speed: 3, Damage: 10, Range: 2)
  - [ ] `Enemy_Orc_Default` (Health: 100, Speed: 2, Damage: 20, Range: 2.5)
  - [ ] `Enemy_Archer_Default` (Health: 40, Speed: 4, Damage: 15, Range: 8)

---

## ✅ Шаг 2: EnemyBase (базовый класс)

**Цель:** Создать базовый класс для всех врагов.

### 2.1. Создание скрипта EnemyBase
- [ ] В папке `Assets/_Scripts/Enemies/` создан скрипт `EnemyBase.cs`
- [ ] Класс наследуется от `MonoBehaviour`
- [ ] Поля: `enemyData` (EnemyData), `currentHealth` (float), `target` (Transform)
- [ ] Свойства: `MaxHealth`, `MoveSpeed`, `Damage`, `AttackRange`, `DetectionRange` (геттеры к `enemyData`)
- [ ] Методы:
  - [ ] `TakeDamage(float damage)` — получение урона
  - [ ] `Die()` — смерть врага
  - [ ] `FindTarget()` — поиск цели (игрока)
  - [ ] `MoveTowardsTarget()` — движение к цели
  - [ ] `Attack()` — атака (базовая реализация)

---

## ✅ Шаг 3: EnemyFactory (паттерн Factory)

**Цель:** Создать фабрику для создания врагов по их данным.

### 3.1. Создание скрипта EnemyFactory
- [ ] В папке `Assets/_Scripts/Enemies/` создан скрипт `EnemyFactory.cs`
- [ ] Класс помечен как `static` или реализован как Singleton
- [ ] Методы:
  - [ ] `CreateEnemy(EnemyData data, Vector3 position, Quaternion rotation)` — создание врага из данных
  - [ ] `CreateEnemy(string enemyName, Vector3 position)` — создание по имени (опционально)
- [ ] Фабрика использует префаб из `EnemyData.prefab` для создания экземпляров

---

## ✅ Шаг 4: EnemySpawner (спавнер врагов)

**Цель:** Создать систему спавна врагов в игре.

### 4.1. Создание скрипта EnemySpawner
- [ ] В папке `Assets/_Scripts/Enemies/` создан скрипт `EnemySpawner.cs`
- [ ] Поля: `spawnPoints` (Transform[]), `enemyDataList` (EnemyData[]), `spawnInterval` (float), `maxEnemies` (int), `spawnOnStart` (bool)
- [ ] Методы:
  - [ ] `SpawnEnemy()` — создание одного врага в случайной точке
  - [ ] `StartSpawning()` — запуск периодического спавна
  - [ ] `StopSpawning()` — остановка спавна
- [ ] В `Start()` или `OnEnable()` запускается спавн, если `spawnOnStart = true`

### 4.2. Настройка спавнера в сцене
- [ ] В сцене создан пустой объект `EnemySpawner`
- [ ] Добавлен компонент `EnemySpawner`
- [ ] Созданы точки спавна (пустые объекты) и добавлены в массив `Spawn Points`
- [ ] В Inspector настроено:
  - [ ] `Enemy Data List` → добавлены ассеты `EnemyData` (Goblin, Orc, Archer)
  - [ ] `Spawn Interval` → `5` секунд
  - [ ] `Max Enemies` → `10`
  - [ ] `Spawn On Start` → `true`
- [ ] Объект сохранён в сцене

---

## ✅ Шаг 5: Создание префаба врага

**Цель:** Создать базовый префаб врага для использования в системе.

### 5.1. Создание префаба EnemyBase
- [ ] В сцене создан объект `Enemy_Base`
- [ ] Добавлен компонент `EnemyBase`
- [ ] Добавлены компоненты:
  - [ ] `CapsuleCollider` (или другой Collider)
  - [ ] `Rigidbody` (если нужна физика)
- [ ] Создан дочерний объект `Visual` для визуального представления (можно использовать простой куб/сферу)
- [ ] В Inspector `EnemyBase` настроено:
  - [ ] `Enemy Data` → `Enemy_Goblin_Default` (или другой)
- [ ] Префаб сохранён в `Assets/_Prefabs/Enemies/Enemy_Base.prefab`
- [ ] Объект удалён из сцены

### 5.2. Связывание префаба с EnemyData
- [ ] Открыт ассет `Enemy_Goblin_Default`
- [ ] В поле `Prefab` назначен префаб `Enemy_Base`
- [ ] Аналогично для других `EnemyData` (можно использовать один префаб или разные)

---

## ✅ Шаг 6: Проверка работы

**Цель:** Убедиться, что система врагов работает корректно.

### 6.1. Проверка в редакторе
- [ ] Префаб `Enemy_Base` содержит компонент `EnemyBase` с назначенным `EnemyData`
- [ ] В сцене есть объект `EnemySpawner` с настроенными точками спавна
- [ ] У `EnemySpawner` назначены ассеты `EnemyData` в списке
- [ ] Слой `Enemy` создан в `Project Settings` → `Tags and Layers`

### 6.2. Проверка в игре
- [ ] Запущена игра через `Bootstrap`
- [ ] Переход в `GameScene` через главное меню
- [ ] При старте игры:
  - [ ] Враги появляются в точках спавна
  - [ ] В консоли логируется создание врагов
- [ ] Враги движутся к игроку (если реализовано в `EnemyBase`)
- [ ] При получении урона враги логируют это в консоль
- [ ] При смерти врага он уничтожается и логируется событие смерти

---

## 📝 Примечания

- **Порядок выполнения важен:** выполняй шаги последовательно, не пропускай этапы.
- **Тестирование:** проверяй работу после каждого шага, особенно после шага 6.
- **Слои:** убедись, что слой `Enemy` создан в `Project Settings` → `Tags and Layers`.
- **Теги:** можно добавить тег `Enemy` для удобного поиска врагов в коде.
- **Наследование:** `EnemyBase` — это базовая реализация. Позже можно создать специализированных врагов (например, `MeleeEnemy`, `RangedEnemy`), наследующихся от `EnemyBase`.
